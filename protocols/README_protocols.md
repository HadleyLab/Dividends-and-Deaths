# Protocols — Execution Manual

## What This File Is

This README is the **execution manual** for *Dividends & Deaths*.

It defines how governed ideas, concepts, and episodes are converted into canonical prose without drift. If prose, drafts, or convenience conflict with these protocols, **the protocols win**.

This file should be read as a *how-to guide* for running the system, not as background documentation.

---

## Purpose

To translate book governance and conceptual canon into **repeatable, enforceable actions**.

Protocols ensure that:
- structure precedes style
- accountability precedes eloquence
- emotion never outruns mechanism
- death remains traceable to system failure

Protocols do not generate meaning. They **enforce it**.

---

## Scope

Applies to all canonical work:
- chapter drafting and revision
- narrative episodes and cases
- figures, tables, and diagrams
- concept reuse and modification

If material is intended to appear in the book, these protocols apply.

---

## Role in the System (Read This When Confused)

The book operates as a layered system:

- `book/` — governance: what must remain true
- `concepts/` — ontology: what is allowed to exist
- `protocols/` — execution: how work is done
- `chapters/` — output: governed prose

Protocols sit **below governance and canon** and **above prose**.

They turn rules into actions.

---

## What Protocols Do (and Do Not Do)

Protocols **do**:
- enforce the spine contract
- bind narrative assets to engines
- make death auditable
- prevent conceptual and emotional drift
- make AI useful without giving it authority
- enforce prose-driven ordering (chapter → scene → ledger)
- enforce production reindexing when prose order changes

Protocols **do not**:
- invent ideas or episodes
- judge truth or morality
- replace human responsibility

They exist so that once a claim is made, it is **structurally upheld**.

---

## Canonical Protocol Structure

Every protocol follows the same enforceable structure:

- **Purpose** — why this protocol exists
- **Scope** — when it applies
- **Inputs** — authoritative documents or assets
- **Outputs** — what must exist when complete
- **Procedure** — step-by-step execution (order matters)
- **Checks** — pass/fail conditions
- **Notes** — constraints and edge cases

If a required section is missing, the protocol is incomplete.

## How to Use Protocols (Minimal Recipe)

1. Start with governance (`book/`) and canon (`concepts/`).
2. Select the protocol that matches the task.
3. Follow the procedure **in order**.
4. Resolve all failed checks before proceeding.

If a protocol blocks progress, fix the input — **do not bypass the protocol**.

---

## AI Review Discipline

Protocol checks include AI-assisted consistency scans where noted (see `protocols/protocol_chapter_build.md` and `AUTHORING_PLAN.md`).

AI never introduces meaning; it only enforces structure, reuse, and contradiction checks.

---

## Author–Protocol Contract

- The author supplies judgment, witness, and intent.
- Protocols supply order, memory, and enforcement.
- Neither replaces the other.

Episodes without protocols become memoir.
Concepts without protocols become abstraction.

This directory exists so the book can be written as a **system**, not a stream of prose.

---

## Non-Negotiables

- Protocols override convenience.
- Prose does not become canonical until protocol-complete.
- Death must remain traceable to engine failure.
- Governance language may not be softened for comfort or speed.

If following a protocol feels slow, that friction is intentional.
