# Chapter Blueprint - Dividends & Deaths

Repeatable workflow for drafting every chapter.

## Required Inputs
- `docs/governance/narrative_asset_compliance.md` - legal and ethical constraints.
- `docs/governance/book_spine.md` - chapter question, claim, and handoff.
- `docs/governance/emotional_arc_map.md` - emotional temperature and grief limits.
- `docs/concepts/concept_vocabulary.md` - canonical definitions and terms.
- `docs/concepts/digital_maya.md` - usage guardrails.
- Relevant entries in `assets/ledgers/` - required before prose.

## Naming Convention (Canonical)
- Prologue is Chapter 00.
- Chapter files use two-digit prefixes: `00_prologue.md`, `01_the_billable_code.md`, `02_dividends.md`.
- Asset ledgers mirror the same numbering and naming in `assets/ledgers/`.

## Chapter Contract
1. Write the Chapter Question / Claim / Exit Handoff block.
2. Confirm alignment with the part-level commitments in the book spine. If not aligned, revise before writing scenes.

## Asset Ledger First
1. Spin up or update `assets/ledgers/NN_chapter_name.md`.
2. For each asset include: ID, type, cultural context, function, reuse hooks.
3. Run the compliance checklist from `narrative_asset_compliance.md` against the ledger before you draft.

## Scene Architecture
- Opening hook: place the ledger's Core Thesis Asset or mirror scene immediately.
- System explanation: insert governance facts within 600 words of any vignette.
- Callback frequency: reuse at least one prior asset per chapter.
- Translation > Extraction > Custody: show this progression to reinforce the spine.

## Tonal Guardrails
- Check the emotional arc table to determine if grief, anger, or agency should dominate.
- After any grief vignette, close the section with a structural cause sentence.
- Maintain observational, inevitable tone per compliance rules.

## Language and Concept Hygiene
- Pull from `concept_vocabulary.md` and reuse mandated phrases (e.g., "Dividends rise. Deaths fall.").
- Introduce jargon using the three-step rule (gentle entry -> imagery -> refresher).
- Mention Digital Maya only when the consequences align with the dedicated guidance doc.

## Verification Checklist (before saving)
1. Compliance: living-person naming rule respected; interior-state prohibition observed.
2. Ledger sync: every scene maps to a logged asset; remove or relocate orphans.
3. Spine alignment: chapter exit handoff tees up the next part's promise.
4. Economic claims: framed conservatively and sourced.
5. Sprinkling rule: at least one reusable hook planted for later chapters.

## Publication Staging
- Update `chapters/README.md` checklist with the chapter status (outline -> draft -> polish).
- If the chapter is ready for external review, bundle its ledger + governance references so the reviewer can audit without additional digging.

Following this order keeps asset governance, emotional flow, and concept precision synchronized so chapters remain publication-ready.
