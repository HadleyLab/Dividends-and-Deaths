# Mortality as Ledger

## Purpose
Define mortality as the final audit of system performance.

## Scope
Applies to chapters that translate system failures into outcomes.

## Category
Lens

## Canonical Definition
Mortality is the downstream ledger: the final, non-negotiable audit of whether a system’s representations were faithful.

## Usage / Placement Rules
- Use when turning abstraction into measurable consequence.
- Avoid treating mortality as tragedy without mechanism.

## Relationship to Canonical Concepts
- **Billable Code:** the code writes the record; mortality closes it.
- **Three Engines:** death occurs when engine failures align.
- **Dividends and Deaths:** mortality is the death half of the ledger.

## Reusable Phrase (Canonical)
“Mortality is the downstream ledger.”

## Death-Bound Clarification
When representation fails and cannot be corrected, mortality becomes the only remaining audit.  
If mortality gaps persist, the system has failed regardless of precision claims.
