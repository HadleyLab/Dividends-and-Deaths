# Concepts — Canonical Ontology Manual

## What This File Is

This README defines the **conceptual canon** of *Dividends & Deaths*.

It specifies what concepts are allowed to exist, how they are defined, and how they may be reused across the manuscript. If prose, protocols, or chapters conflict with this directory, **this directory wins**.

This file should be read as an ontology manual, not a thematic guide.

---

## Purpose

To lock the book’s **meaning layer** so it can scale without drift.

These rules ensure that:
- language remains precise
- concepts are reusable without redefinition
- narrative episodes and analysis remain interoperable
- harm and death are framed as system outcomes, not metaphors

Concepts are not vibes, themes, or motifs. They are **binding definitions**.

---

## Scope

Applies to:
- all chapters
- all protocols
- all figures and captions
- all editorial passes

If a term is doing conceptual work in prose, it must be defined here.

Nothing in this directory is illustrative.

---

## Role in the System (Read This When Confused)

The book is organized as a layered system:

- `book/` — governance: what must remain true
- `concepts/` — ontology: what is allowed to exist and what it means
- `protocols/` — execution: how work is done
- `chapters/` — output: governed prose

Concepts sit **below governance** and **above execution**.

They constrain interpretation but do not dictate prose.

---

## Concept Categories (Closed Sets)

All concepts must belong to **one and only one** category:

### Vocabulary
Core terms and canonical phrases whose meanings must remain fixed.

### System Primitives
Structural elements of the precision medicine economy (e.g., engines, geometry).

### Lenses
Framing constructs with strict placement rules (e.g., Digital Māyā).

### Governance Constructs
Enforceable constraints that bind representation to consequence (e.g., Ma’at, custody).

### Policy Context
Legal or regulatory structures mapped to specific chapters (e.g., healthcare data law).

If a concept cannot be cleanly classified, it is not ready for canon.

---

## Canonical Concept Structure (Required)

Every concept file must include:

- `## Purpose`
- `## Scope`
- `## Canonical Definition`
- `## Usage / Placement Rules`
- `## Relationship to Canonical Concepts`
- `## Reusable Phrase (Canonical)`
- `## Death-Bound Clarification`

Concepts are definitions, not essays.

---

## Death-Bound Requirement (Non-Negotiable)

Any concept that touches:
- harm
- exclusion
- disparity
- error
- automation
- scale

**must** explicitly explain how misuse, absence, or failure contributes to patient harm or death.

If this cannot be stated plainly, the concept does not belong in this book.

## Author–Concept Contract

- The author supplies synthesis and invention.
- The canon supplies constraint and memory.
- Neither replaces the other.

Episodes without concepts become anecdote.
Concepts without episodes become abstraction.

This directory exists to keep the book **intelligible at scale**.

---

## Non-Negotiables

- Concepts override prose when conflicts arise.
- Concepts may not be redefined casually or implicitly.
- Closed sets remain closed unless governance changes.
- Any concept that touches harm must remain death-bound.

If a passage violates a concept definition, the passage is wrong.
